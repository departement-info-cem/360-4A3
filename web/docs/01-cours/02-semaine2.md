title: 🔍 Exploration et cadrage du projet (10%)
description: Semaines 2 à 4
---

Les semaines 2 à 4 sont consacrées à l’**exploration**, au **raffinement** et au **cadrage scientifique** de votre projet.

👉 L’objectif n’est **pas encore** de produire des résultats définitifs, mais de construire un projet :

- clair
- réaliste
- scientifiquement cohérent

Ces semaines mènent directement à la remise de la [Proposition de projet](/cours/semaine5) et à la [Présentation du projet proposé](/cours/semaine6).

:::info-nt
## 🎯 Objectifs

Durant cette période, vous devez :

- formuler une **question de recherche claire**
- identifier des **données ou une expérience numérique réaliste**
- comprendre les **enjeux scientifiques** du projet
- explorer différentes pistes
- proposer une **démarche cohérente**
- ajuster vos choix en fonction de ce que vous découvrez

👉 L’exploration est une démarche **individuelle et collective** : chaque membre doit contribuer activement au développement du projet.
:::

## 🧭 Ce sur quoi vous devez travailler

:::tip-nt
### 🧠 Clarifier la question

Votre question de recherche doit progressivement devenir :

- plus précise
- mieux délimitée
- compatible avec une expérience numérique

👉 Une question floue est un signal qu’il faut **ralentir et clarifier**, pas foncer.

📌 Référez-vous régulièrement à [Formuler de bonnes questions de recherche](/methodes/questions-recherche).
:::

:::note-nt
### 📂 Explorer les données

Selon votre projet, vous devez :

- explorer des **sources de données potentielles**
- ou définir clairement une **expérience numérique ou simulation**

À ce stade, il ne s’agit **pas** d’analyser en profondeur, mais de vérifier :

- que les données existent
- qu’elles sont accessibles
- qu’elles sont compréhensibles
- qu’elles sont adaptées à votre question

📌 Consultez [Comment évaluer la qualité d’un jeu de données?](/methodes/source-donnees).
:::

:::info-nt
### 🧪 Explorer différentes pistes

Commencez à réfléchir et à faire des essais pour déterminer :

- comment vous pourriez répondre à votre question
- quelles comparaisons ou mesures seraient pertinentes
- quels paramètres pourraient être étudiés
- quelles méthodes pourraient être utilisées
- quelles visualisations pourraient aider à l’analyse

👉 Il est normal que votre démarche **évolue** pendant ces semaines.

Un essai qui ne fonctionne pas peut être tout aussi utile qu’un essai réussi s’il vous permet de mieux comprendre le problème ou d’ajuster votre démarche.
:::

:::warning-nt
### ⚠️ Ajuster l’ambition

C’est souvent pendant ces semaines que l’on réalise que :

- le projet est trop large
- les données sont trop complexes
- certaines idées sont irréalistes dans le temps disponible
- une autre approche serait plus pertinente

👉 Ajuster ou simplifier un projet est **une décision scientifique saine**, pas un échec.
:::

## 📓 Journal de bord individuel

:::tip-nt
Chaque membre de l’équipe doit tenir un **journal de bord individuel** dans le repo GitHub de l’équipe.

Créez un dossier :

```text
journal/
```

avec un fichier Markdown (`.md`) par membre :

```text
journal/
├── prenom-nom.md
├── prenom-nom.md
└── prenom-nom.md
```

Le journal doit être mis à jour **régulièrement pendant la période d’exploration**, et non reconstitué à la fin.

👉 Le journal doit rester **très bref**. Son objectif est de conserver une trace de votre démarche, pas de vous ajouter un travail de rédaction.
:::

### ✍️ Format d’une entrée

Pour chaque entrée, utilisez simplement :

```md
## 15 septembre

**Travail réalisé**
- Exploration d’un jeu de données
- Recherche de différentes méthodes possibles
- Test d’une première approche

**Résultat / problème**
L’approche testée nécessite des données que nous n’avons pas.

**Prochaine étape**
Chercher une autre méthode ou une autre source de données.
```

Il n’y a **aucun nombre de mots attendu**.

Une entrée peut être très courte si elle permet de comprendre :

1. ce que vous avez fait;
2. ce que vous avez appris, obtenu ou rencontré comme problème;
3. ce que vous prévoyez faire ensuite.

:::info-nt
### 🔎 À quoi sert le journal?

Le journal constitue une **trace de votre travail individuel**.

Il sera utilisé avec les autres traces disponibles dans le projet — par exemple les commits GitHub, fichiers, recherches, essais, analyses ou résultats — pour évaluer votre contribution et votre progression.

👉 Vous n’êtes pas évalué sur la qualité de votre français dans le journal. Il doit simplement être **régulier, clair et fidèle au travail réalisé**.
:::

## 📝 Préparer la proposition

:::danger-nt
Durant cette période, votre équipe doit également commencer à préparer la [Proposition de projet](/cours/semaine5).

Vous devriez le plus tôt possible :

- télécharger le gabarit de projet
- créer votre projet dans **Typst Web**
- partager le projet Typst avec tous les membres de l’équipe
- commencer à rédiger les différentes sections de la proposition
- commencer à préparer la [Présentation du projet proposé](/cours/semaine6)

⚠️ Ne laissez pas toute la rédaction à la dernière minute!

👉 Le document Typst commencé ici sera conservé et évoluera progressivement jusqu’à devenir votre **article scientifique final**.
:::

## 🤝 Rencontres hebdomadaires

:::info-nt
Chaque semaine, votre rencontre d’équipe avec moi servira à :

- discuter de l’avancement
- valider vos choix
- identifier des problèmes potentiels
- ajuster la direction du projet
- planifier les prochaines étapes

👉 Venez préparés à expliquer :

- ce que vous avez essayé
- ce que vous avez compris
- ce qui fonctionne
- ce qui ne fonctionne pas
- ce qui est encore flou
:::
